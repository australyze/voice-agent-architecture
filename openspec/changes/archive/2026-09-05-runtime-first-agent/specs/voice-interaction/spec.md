## MODIFIED Requirements

### Requirement: Media identity is not business state

The runtime MUST keep channel or media identity distinct from product business state. This change MUST NOT introduce conversational memory or persist Session or ConversationTurn tables. A successful agent turn MUST NOT advance a product business workflow.

#### Scenario: Successful placeholder does not create business state

- **WHEN** the runtime handles a valid voice turn
- **THEN** it returns a structured agent reply without writing a product Session aggregate or changing a business workflow status

#### Scenario: External channel id stays opaque

- **WHEN** an inbound turn includes a provider call or conversation identifier
- **THEN** the runtime treats it as an opaque external channel identifier and does not use it as the internal session primary identity unless no internal session identifier was supplied

## REMOVED Requirements

### Requirement: Runtime returns a deterministic placeholder reply

**Reason**: The first demo agent now owns reply text. A non-LLM placeholder no longer proves the runtime.

**Migration**: Voice-turn success tests MUST assert a schema-valid agent reply from the runtime (mocked LLM in CI), not locale placeholder copy.

## ADDED Requirements

### Requirement: Runtime returns a runtime-owned agent reply

Given a valid internal voice turn, the application runtime MUST produce a structured reply owned by the runtime agent-turn path. The reply text MUST come from a schema-valid agent `reply` decision after any authorized tool hop. The reply MUST NOT be generated by the voice vendor or by adapter-local business rules. Locale for the reply MUST come from the turn or configuration, not from a hard-coded domain language rule. The default configured locale remains Spanish (`es`). Tests that use a mocked LLM MUST remain deterministic for the same fixture and locale.

#### Scenario: Valid turn yields agent reply

- **WHEN** the runtime handles a valid voice turn and the mocked or configured LLM returns a schema-valid reply
- **THEN** it returns a structured reply whose text is the agent `replyText` for the configured locale and the LLM port is used

#### Scenario: Same mocked input is deterministic

- **WHEN** the runtime handles two equivalent valid voice turns with the same configured locale and the same mocked LLM fixture
- **THEN** the structured reply content is the same


### Requirement: Agent failures map to typed voice-safe errors

When the agent-turn path fails, the voice-turn result MUST remain a typed voice error with a stable code and a safe message. Agent `llm_timeout` and `tool_timeout` MUST map to the existing voice timeout classification. Other agent failures MUST map to an existing voice-safe code or an added voice-safe code that does not leak internals. Stack traces, secrets, and raw model output MUST NOT appear on the structured voice error.

#### Scenario: Agent timeout is a voice timeout

- **WHEN** agent handling exceeds the configured voice handling timeout or the LLM time budget
- **THEN** the voice-turn result is a timeout voice error and does not leave an unbounded wait

#### Scenario: Invalid model output is voice-safe

- **WHEN** the agent-turn path fails with `invalid_output`
- **THEN** the voice-turn result is a typed error with a stable code and a safe message and omits raw model output
